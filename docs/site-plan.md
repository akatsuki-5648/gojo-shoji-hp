# サイト設計メモ

## 構造改革の方針

前回版の問題:

- 未確認の事業内容を仮の商品・サービスとして載せていた。
- 商品カード、FAQ、サービス3分類などが一般的なテンプレート構造に寄っていた。
- セクション順がよくある会社サイトに近く、独自性が弱かった。
- 直角カードと整然としたグリッドが、既存制作物と重複して見える危険があった。

今回版の方針:

- 確認できる事実だけを載せる。
- 架空の物件、架空の価格、架空の取扱種別を置かない。
- レイアウトは斜めのセクション、縦見出し、名刺スキャン、台帳型表示に変更する。
- EC対応は「空の物件掲載台帳」として用意し、実データが入るまで商品化しない。
- AI検索向けには、会社名、住所、免許番号、電話番号を強く、短く、整合的に示す。

## ページ構成

1. Hero
   - 名刺画像を大きく見せる。
   - 「確認できることだけを掲載する」方針を先に出す。
   - 電話と問い合わせ欄への導線を置く。

2. Confirmed Facts
   - 法人名、法人番号、所在地、免許番号、電話、FAX、メール、名刺氏名、所属団体を台帳表示。

3. Listing Ledger
   - 物件情報は未登録と明記。
   - 実データ登録時の必須項目だけを示す。
   - 架空のカテゴリや価格を置かない。

4. Local Signal
   - 所在地とAI検索上の整合性を示す。
   - 地図リンクを置く。

5. Contact
   - 未確認の相談種別を選択肢化しない。
   - 自由記入欄のみ。

6. Sources
   - 掲載根拠と掲載しない情報を明示。

## デザイン方針

- 直角に積むだけのカード型構成から離れる。
- セクション境界に `clip-path` の斜め区切りを使う。
- 配色は、名刺の白黒に対して、黒緑、銅色、金、青灰を重ねる。
- 角丸を減らし、台帳・証跡・名刺スキャンの印象を出す。
- スマホでは斜め区切りを浅くし、横スクロールを出さない。

## 本番化する場合の追加条件

本番公開で情報を増やす場合は、会社側または確実な公開情報で確認してから追加する。

- 営業時間
- 定休日
- 公式URL
- 代表者情報
- 物件情報
- 取扱種別
- 会社写真
- 実績
- レビュー
- フォーム送信先
